# Rules

1. Always plan your implementation and ask for my review before you start the execution or updating any of my codebase.
2. We should follow a Test Driven Development (TDD) approach. We write a good test and then the implementation and then refactor. I need a quality codebase with deterministic expectations.
3. Don't commit anything to git unless I strictly tell you to.
4. When approved to commit to git, please use a descriptive and detailed message.
5. Before you write a code or update any file in my codebase, we must first plan it very well. Then, I will review and approve before you apply the changes to my codebase. This apply to all code changes, whether you are writing a test suites or implementation, we must review your thought process and the code changes. Only when I approve it that you make the changes to the codebase.
6. I don't need any form of an assumption or theoretical guesses. You strictly verify everything before giving me a feedback, suggesting, or making any code changes or fixes. When necessary review the entire codebase to refresh your memory and understanding the codebase. I don't need false claims or useless and blind fixes. You can research online to validate your hypothesis.
7. No false claims.
8. Don't overwrite any file, only update but never overwrite. (I REPEAT, DON't OVERWRITE FILES).
9. NO MONOLOGUE COMMENTS IN THE CODEBASE. I REPEAT, NO MONOLOGUE COMMENTS IN THE CODEBASE. I STRICTLY PROHIBIT IT AT ALL COSTS.
10. Follow DRY (Don't Repeat Yourself) principles and make sure that you always write clean code.
